# Choreographing screen recordings and demos

Most build-in-public footage is a screen recording. It fails when it shows activity instead of an outcome.

## Before recording (script the run, then rehearse once)
1. Decide the single outcome the viewer must see (a result, a generated asset, a passing test, a number changing).
2. Prepare state: clean desktop, one window, dark or light theme chosen deliberately, font size 16 pt+ in terminals,
   browser zoom 125-150 percent, notifications off, bookmarks/tabs hidden, no secrets visible.
3. Pre-load everything slow. If a step takes 40 s in real life, record it, then handle it in the edit (cut or
   speed-ramp with a visible "2x" label). Never hide slowness without saying so.
4. Write the 3-line voiceover or caption script first. Record in short takes: setup, action, result.

## While recording
- Move the cursor with purpose; park it still while something important happens. No circling.
- Narrate or caption what the viewer should look at BEFORE it appears, not after.
- Pause 1 s on the result. Hold the key number or output longer than feels natural (1.5-2 s minimum).
- Capture the failure honestly if there was one; a real error followed by a fix is better proof than a perfect take.
- Record 5 s extra at head and tail.

## In the edit
- Open on the result or the most interesting frame, then show how you got there (result first, process second).
- Punch in on the 1-3 pixels that matter: crop to the region, scale so text is readable on a phone.
- Cut dead time: loading, typing pauses, cursor wandering. Keep typing only when the typed text IS the content,
  and speed it.
- One focal point per shot. If two things happen on screen, add an arrow or highlight to the one that matters.
- Add a freeze-frame or hold on the final result with a one-line text card.
- Combine with a face or hands clip (even 3 s) when trust matters; a human frame breaks monotony.
- Do not fake outputs. Edit order may change, but every result shown must be real and from this run.

## Typical beat map for a 25-35 s build-in-public clip
0-2 s result or number on screen + hook text | 2-8 s what it is (one line) | 8-20 s the run, with 2-3 punch-ins |
20-26 s the result held, number visible | 26-32 s honest gap or next step + one line ask.
