# Rendering and publishing

How generated content becomes a static page, how localized routes are built,
and how a reviewed topic reaches `frontend/`. The rule that governs every
change here: **the renderer emits content and hooks; the shell owns chrome;
only the owning publish flow writes the live tree.**

Sources: `factory/render.py`, `factory/link.py`, `factory/translate.py`,
`scripts/publish-frontend.sh`, `scripts/gen-seo-files.py`,
`docs/specs/frontend/shell-injection.md`, `docs/specs/frontend/seo-plan.md`,
`docs/deployment/docker.md`, and `docs/frontend/design-doctrine.md`. Dated
**2026-11-14**.

## 1. Ownership boundary

| Layer | Owned by | Examples | How it reaches a page |
|---|---|---|---|
| Content-only lesson HTML, manifest, staging site | `factory/render.py` (generated) | `index.html`, `manifest.json`, `page.js`, `page.css` | `06-render` into `runs/<run_id>/06-render/site/` |
| Shared shell JS/CSS | `frontend/assets/zivon.js`, `zivon.css` (hand-maintained) | read-aloud, report, consent, voice dock, privacy link, language bar, telemetry, `ZivonSim`, `LessonKit` | loaded by every page; injected idempotently at runtime |
| Landing/catalogue shell | `frontend/index.html` (hand-maintained) | course cards, grade jump-nav, empty state | reads `window.ZIVON_COURSES` |
| Catalogue data | `factory/render.py::write_courses_js` (generated) | `courses.js` | regenerated by `06` (staging) and `11-link` (published) |
| Localized routes/bundles | `factory/render.py::render_localized` (generated) | `<locale>/index.html`, `i18n/<locale>.json`, `i18n.js`, locale hubs | `10d-transrender` |
| Narration assets | `factory/narration/` (generated) | `audio/<course_id>/*.opus`, `narration-manifest.json` | `12-narration` after `11-link` |
| SEO files | `scripts/gen-seo-files.py` (generated) | `sitemap.xml`, `robots.txt` | publish flow, never hand-edited |
| Published snapshot | `scripts/publish-frontend.sh` | `frontend/courses/**`, `frontend/courses.js`, `frontend/audio/**` | mirror from the cluster PVC |

Consequences:

- Do **not** add product chrome (read-aloud buttons, dock, consent, report,
  language bar) to `factory/render.py`. It belongs in `zivon.js`, which is
  idempotent and content-first. A generated page must remain readable with JS
  off.
- Do **not** hand-edit `frontend/courses/**`, `courses.js`, or `audio/**`. Fix
  the producer and re-publish.
- Do **not** bake generated pages into an image. `Dockerfile.frontend` bakes
  only the hand-maintained shell; the generated tree is volume-mounted/served.

## 2. `06-render`: the page contract

### Inputs

`chapter`/`source_pack`, `lesson`, `blocks`, `05-interactive` fragments, the
shared shell assets, and the configured frontend path. No model call.

### Outputs

- `runs/<run_id>/06-render/site/` — staging site with `index.html`, `assets/`,
  `courses/<course_id>/<slug>/`, `courses.js`.
- `runs/<run_id>/06-render/site/courses/<course_id>/<slug>/index.html`
- optional `page.js` and `page.css` (only when simulations produced fragments)
- `manifest.json` next to the page
- `runs/<run_id>/06-render/output.json` = `{topic_dir, site_dir, manifest, files}`

The slug comes from the chapter title (`slugify(display_title)`), the course
folder from the located chapter's class (`class-N-physics`). The model's
`lesson.title` is recorded as `lesson_title` but never names the directory.

### Page anatomy (content-only)

Every generated lesson page carries:

- `<!doctype html>`, `<html lang="en">`, viewport meta, strict CSP meta,
  canonical + `hreflang` links;
- `assets/zivon.css` and local fonts (no CDN);
- `<main class="zn-page">` with a header (kicker, title, objectives), ordered
  blocks, a glossary section, and a sources footer with visible citations;
- `assets/zivon.js` at the end; optional `page.js` / `page.css`;
- stable `id="b-NN"` on every block (anchor, read-aloud, tutor highlight);
- every visible lesson string either carries `data-i18n` or comes from the UI
  string bundle on localized routes.

CSP:

```text
default-src 'none'; style-src 'self'; script-src 'self'; img-src 'self' data:;
font-src 'self'; connect-src 'self'; media-src 'self'; base-uri 'none'
```

Lesson pages are the pages that relax `connect-src` to `'self'` for the voice
dock (ADR-0020) and add `media-src 'self'` for narration audio. `/privacy/` has
its own scoped policy; every other location keeps `connect-src 'none'` at the
nginx server level. The relaxation is per-page, not site-wide.

### Block rendering

- `text` → paragraphs.
- `worked_example` → problem, ordered steps, answer.
- `check` → keyboard-native fieldset with radios (MCQ) or a numeric input,
  `aria-live` feedback, retry, and a "Why?" explanation. MCQ and numeric both
  render. The shell wires the behavior; the renderer emits the markup.
- `reveal` → native `<details>`/`<summary>`; keyboard accessible with zero JS.
- `diagram` → inline SVG exactly as authored; presentation attributes only;
  no script/style/external refs.
- `simulation` → canvas + controls + `.zn-sim-read` live readout + description;
  `ZivonSim.register("<block_id>", {init, draw})` is supplied by `05`; the
  shell runtime owns rAF, reduced motion, control wiring, and the on-canvas
  error painter.

### Deterministic gates inside `06`

`lint_generated(page_js, page_css, html_text)` runs before the page is
written. A hit raises `LintError`; the renderer never ships a lint-broken page.
The lint set includes no `eval`/`new Function`/`document.write`/dynamic
import/network APIs/string URLs/inline scripts, no external HTML `src`/`href`,
no CSS `@import`/external `url()`, and `page.css` selectors scoped under
`.zn-sim-<id>` with no canvas sizing.

## 3. `10d-transrender`: localized routes and bundles

- Renders `<topic>/<locale>/index.html` for each available locale, plus
  `i18n/<locale>.json`, `i18n/en.json`, and `i18n.js`.
- Renders locale hub pages at `site/<locale>/index.html` (e.g. `/hi/`), which
  list the localized catalogue.
- Amends the topic `manifest.json` with `default_locale`,
  `locales_available`, `titles_by_locale`, `translation_status`, and
  `i18n_hashes`.
- Regenerates the staging `courses.js` so entries carry locale metadata.
- Does **not** publish; `11-link` copies the localized tree.

Contract details (CP-TRN-002/003/004):

- Diagram `<text>` strings are extracted to `svg_texts`, translated, and
  re-injected with `data-i18n`; the model never reads or emits raw `<svg>`.
- Simulation canvas strings use `ctx.t_str(key, fallback)`; the shell updates
  `ctx.locale` and redraws once when the language chip changes, preserving
  slider values. Older `page.js` files without `t_str` still localize DOM
  chrome.
- The manifest's `translation_status` records verified/fallback per locale and
  the glossary version. A block with no verified translation must show the
  "not available yet" marker, never English pretending to be Hindi.

**Known gap:** localized hubs load the same `courses.js`, whose hrefs point at
the English `index.html`; the catalogue renderer does not rewrite hrefs per
locale. Fix in the owning flow (renderer/shell) with a test, not by editing
`courses.js`.

## 4. `11-link`: publish and integrity

`factory/link.py::run(cfg, run_ctx, render_out)` is the only stage that writes
`frontend/`.

Steps:

1. Copy the topic directory from the staging site to
   `frontend/courses/<course_id>/<slug>/`, replacing the previous version.
2. **Prune stale same-chapter duplicates.** Read the new `manifest.json`.
   For every sibling `*/manifest.json` in the same course directory, if it has
   the same `course_id` and the same `chapter.title` but is not this topic,
   delete it. The previous version survives in git history after publish. This
   exists because older runs named the directory after the model's lesson
   headline, producing two pages for one chapter.
3. Copy top-level locale hubs (`site/<locale>/index.html` →
   `frontend/<locale>/index.html`) for every locale with a hub.
4. Regenerate `frontend/courses.js` with `write_courses_js`.
5. Smoke-test every href in `courses.js` and every declared locale file; a
   missing target raises `StageError`.

Output: `runs/<run_id>/11-link/output.json` with the entries, `course_count`,
pruned names, and published hubs.

What `11-link` does **not** do:

- regenerate `sitemap.xml` / `robots.txt` (publish flow only);
- write a `catalogue.json` or DB import;
- add status/language/count metadata beyond what the manifest carries;
- guarantee a homogeneous pipeline version across the live tree.

Those are tracked gaps; if your change touches them, own the producer and add
tests instead of patching output files.

## 5. Catalogue and ordering

`write_courses_js` is the only generator. It reads manifests, builds entries,
and sorts by:

```text
class -> chapter_number is None -> chapter_number -> chapter.casefold() -> title
```

So unnumbered topics sort last, and a class-grouped catalogue reads in textbook
order regardless of run order. NCERT chapter numbers run continuously across
parts (e.g. Class 11 Part II starts at 8); the manifest carries the number.

A catalogue entry must resolve. `11-link` fails if any `href` or declared
locale file is missing. The landing shell's `renderCourses()` is the consumer;
do not duplicate the ordering logic there.

## 6. SEO and the publish flow

- **Canonical and `hreflang`** are emitted by `06-render` per page.
- **`sitemap.xml` / `robots.txt`** are generated by
  `scripts/gen-seo-files.py`, invoked by the publish flow. They are never
  hand-edited.
- **`scripts/publish-frontend.sh`** mirrors the cluster-built generated output
  (`courses/`, `courses.js`, and additively `audio/`) from the
  `zivon-frontend` / `zivon-sources` PVC into the repo's `frontend/` snapshot.
  It is founder/owning-flow run, not an agent step in a feature PR.
  - Its staleness guard compares the PVC `courses/` against the repo snapshot;
    if identical, it exits 2 rather than silently republishing an older topic.
  - A narration-only re-publish can also exit 2 before reaching the audio
    mirror because the pages are unchanged; re-trigger the topic if you need a
    fresh snapshot.
- **`frontend/` is the versioned, standalone-deployable snapshot.** Git history
  is the version rotation. A re-publish wholesale-replaces a topic; it does not
  merge.
- **nginx** serves `/audio/` immutable (`max-age=31536000`) with a per-IP audio
  rate limit. Lesson/`/courses/` and `/privacy/` get the scoped CSP; every
  other location stays `connect-src 'none'`.

**Known gap:** committed `sitemap.xml` / `robots.txt` are placeholder
`zivon.local` and stale (fewer URLs than the catalogue); `11-link` does not
regenerate them. Treat a direct `pipeline.py` + `11-link` as leaving SEO stale.

## 7. Integrity checks to preserve

These are load-bearing; a renderer or publish change must keep them green:

- every block has `id="b-NN"`;
- page has doctype, viewport, CSP, canonical, `hreflang`, `main.zn-page`,
  header, ordered blocks, glossary, sources footer, `zivon.js`;
- no external requests, no inline scripts/styles, scripts only from `'self'`;
- every check is keyboard-native with `aria-live` feedback and an explanation;
- every diagram is inline SVG with no script/style/external refs;
- every simulation uses `ZivonSim.register`, canvas 2D, controls, `.zn-sim-read`,
  and a description;
- `page.css` is scoped under the block's `.zn-sim-<id>` and does not size the
  canvas;
- localized pages carry `data-i18n` on visible lesson strings and a visible
  "not available yet" marker for untranslated content;
- every `courses.js` href and declared locale file resolves;
- zero console errors, no horizontal overflow at 360 px, within the perf
  profile.

## 8. Safe change recipes

### Add a manifest field

1. Decide who reads it. No consumer → additive, low risk. A later stage or the
   shell → the consumer must handle absence, or old artifacts are stale.
2. Add it in `factory/render.py` (base) or `render_localized` / narration
   publish (additive).
3. Update `docs/content-factory/blocks-schema.md` or the architecture doc.
4. Add a render unit test and, if it affects the catalogue, a
   `write_courses_js` test.
5. Decide the resume/version impact explicitly (see
   [artifacts-and-schemas.md](artifacts-and-schemas.md) §9).

### Add a content hook (`data-*`)

1. Confirm the shell contract in `docs/specs/frontend/shell-injection.md`.
2. Emit it in `_render_block` / `_page_html` without changing visible content.
3. Add a static-shell test in `testing/frontend/` (no browser needed for an
   attribute contract).
4. Do not add chrome; a hook is data, not behavior.

### Change catalogue ordering

1. Change `write_courses_js` only; the landing shell must not duplicate the
   sort.
2. Add a unit test with numbered and unnumbered entries across classes.
3. Re-run `11-link` (code-only, no model call) or publish a fresh artifact.

### Add a locale route or SEO metadata

1. Own it in `render_localized` or `scripts/gen-seo-files.py`; never hand-edit
   the output.
2. Add a localized-page test (href, i18n bundle, hreflang, marker behavior).
3. Update `docs/specs/frontend/seo-plan.md` and the manifest/i18n contract if a
   field changed.

## 9. Testing

Run the smallest check that proves the contract:

```bash
python -m unittest discover -s testing/content_factory/unit -t .   # render/link/manifest
python -m unittest discover -s testing/frontend -t .               # shell + static site contracts
python -m unittest discover -s testing/translation -t .            # localized routes/bundles
python3 scripts/check_specs.py
```

`scripts/gen-seo-files.py` is a generator, not a checker; run it only through
the publish flow with the production base URL (or `--allow-placeholder` for a
local dry run). Browser/perf changes need Chromium installed; a skipped browser
test is reported as skipped, never as passed. The perf harness can be run
standalone:

```bash
python -m testing.content_factory.perf.harness \
  --url file:///path/to/page.html \
  --profile testing/content_factory/perf/profiles/weak-android.json
```

## 10. Anti-patterns

- Adding a read-aloud button, dock, consent sheet, or language bar to
  `factory/render.py`.
- Hand-editing a generated `index.html`, `courses.js`, or `sitemap.xml`.
- Editing `frontend/assets/zivon.js` from a pipeline PR; the shell owner owns
  it.
- Making a page depend on a CDN, external font, or network call.
- Adding inline `<script>` or `style=` to a generated page.
- Sizing a canvas or restyling a kit class from `page.css`.
- Publishing a page that did not pass `09/10` because "only a small field
  changed".
- Copying a defect from a live page because it is live; match the best page and
  the tests.
- Forgetting the stale-duplicate prune when changing topic identity.
- Publishing a narration-only change through the page staleness guard and
  calling the exit-2 a failure.
