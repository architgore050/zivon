# Art direction

The landing page is **Field Notes §1–§9**, applied to a page whose job is to be
read in ten seconds and remembered. It is not a lesson page, and it is not a
SaaS template. This file decides composition, emphasis, and artifacts; it does
not add tokens.

**Authority chain.** `docs/frontend/design-doctrine.md` is founder-authored and
wins every conflict. Then `frontend/assets/zivon.css` (the kit) and
`docs/frontend/design-doctrine-example.html` (the reference implementation —
open it and match its patterns rather than re-deriving the look). Then this file.
If a value here disagrees with the doctrine, the doctrine is right — and this
file has a bug worth fixing in the same PR.

## 1. What the base doctrine already decides

These are not suggestions to be re-litigated per page.

| Rule | What it means on a landing page |
|---|---|
| Paper-yellow ground (`--paper`), dark ink (`--ink`) | the page is warm paper with dark type, not white with grey cards |
| Graphite (`--graphite`) for labels, captions, sources | secondary text is a *darker grey-brown*, never a lighter grey |
| Pen-blue (`--pen-blue`) for the one annotation | one blue mark per screen, and it is the only blue on the page |
| Pencil-red (`--pencil-red`) only for gaps and honest corrections | never a red CTA, never a red "sale" badge |
| Tick-green (`--tick-green`) only for done marks | no green success confetti |
| Bricolage Grotesque for display and body | the brand voice is a characterful grotesque, not Inter |
| Courier Prime for notes, numbers, timestamps, sources | data and provenance look *logged*, not claimed |
| Square or 4 px corners | no 16 px rounded cards, no pills for everything |
| Flat surfaces | no gradients, glass, blur, grain, or drop shadows |
| 70% paper / 25% ink / 5% pen-and-pencil | the page is mostly empty paper, and that is the design |
| Left-aligned, generous space | no centred marketing stack, no full-bleed hero carousel |
| One slight rotation, max 1.5°, on one card element only | never on body text, never on the hero headline |

The doctrine's one permitted shadow is the **2 px hard offset on a taped
screenshot** (§6). It is a material cue — "this is a photo of a real page" — not
a depth effect. Nothing else on a landing page casts a shadow.

## 2. Composition

### 2.1 The hero is asymmetric

A landing hero in this system is two things of different weight, not a centred
stack:

```
+---------------------------------------------------------------+
| wordmark                      courses  method  log in  [start]|
+---------------------------------------------------------------+
|                                                               |
|  Ask the page. Out loud.              +---------------------+  |
|  In the language you think in.        |                     |  |
|                                       |   real lesson page  |  |
|  Class 9-10 Physics · EN/हिं/Hinglish   |   or sim, taped,    |  |
|                                       |   one pen circle    |  |
|  [ Open a chapter ]   no account      |                     |  |
|                                       +---------------------+  |
|                                                               |
+---------------------------------------------------------------+
```

Rules:

- **One asymmetry per screen.** A second diagonal (a tilted card beside an
  angled headline) makes the page look broken rather than composed.
- **The text column is narrower than the artifact's.** Type is read in a column;
  artifacts are read as objects.
- **The artifact sits on the optical right** on desktop and **above the CTA** on
  mobile when the headline depends on seeing it, below the CTA when it does not.
- **The empty space is the layout.** If the hero looks "unfinished" to a
  template-trained eye, it is probably right.

### 2.2 The one pen annotation

Exactly one blue mark per screen, generated by the doctrine's pen-underline
algorithm (§4.1), never a CSS `text-decoration` or `border-bottom`.

The doctrine caps the mark at **one per image or post** (§4). A landing page is
neither, so the conservative reading — and the one this bundle uses — is one per
**screen**. The founder can relax that to one per page; nothing here should be
read as loosening the cap.

Where it goes, in priority order:

1. **On the artifact**, circling the thing the headline claims — the highlighted
   sentence in the lesson, the moving quantity in the simulation.
2. **On one word in the H1**, when the artifact cannot carry it.
3. **On a number** that is the proof ("20 s", "Class 10").

It never goes on:

- a link or a button (it reads as a focus state),
- a word that is also emphasised another way,
- more than one element, ever.

The annotation is the page's "look here". If everything is marked, nothing is.

### 2.3 Real product artifacts

The strongest visual asset on the page is the product itself.

- A **real screenshot** of a real page, at a real viewport, with real content —
  taped at the corners, one pen circle, 2 px hard offset.
- A **real transcript** of a real voice turn, in Courier Prime, with the anchor
  chip visible.
- A **real diagram**, drawn clean (§10.7's geometry rules apply to any diagram,
  even outside a lesson), with one handwritten annotation arrow if it needs one.

Not allowed as the primary artifact: a mockup of a page that does not exist, a
Figma frame, a stock photo of a student, a 3D device render, an abstract
visualisation of "AI".

If the product is not ready to screenshot, the page is early. Write the claim
ledger and ship the page when there is something real to show; a beautiful
mockup is a debt that comes due at the first click.

### 2.4 Whitespace and proportion

- **Space is the cheapest signal of confidence.** A page that fills every band
  reads as anxious.
- Keep the doctrine's 70/25/5 ratio visible: most of the viewport is paper.
- Separate sections with space and a single hairline rule in `--rule`, not with
  cards, boxes, or alternating background bands. (The colour and opacity are the
  doctrine's §4 rule; a 1 px web hairline is this bundle's adaptation of the
  2 px post rule.)
- Never put every section in a card. Cards on this page mean "this is an object
  you can act on", and the only object is the artifact and the demo.

## 3. Typography

Use the kit's families and the kit's sizes wherever they exist. The landing page
needs a display size the lesson kit does not carry, so the following is recorded
as a **derivation for the founder's verdict**, not as a new token:

| Role | Size / line | Weight | Family | Note |
|---|---|---|---|---|
| Hero H1 | `clamp(2.75rem, 7vw, 5rem)` / 1.02 | 800 | Bricolage | ≤ 9 words; never all-caps |
| Section headline | `clamp(1.75rem, 3.4vw, 2.5rem)` / 1.1 | 700 | Bricolage | a claim, not a label |
| Lead paragraph | `1.25rem` / 1.45 | 500 | Bricolage | one per screen at most |
| Body | `1.125rem` / 1.55 | 500 | Bricolage | never below 1rem on mobile |
| Data, sources, timestamps | `0.875rem` / 1.3 | 700 | Courier Prime | labels, numbers, citations |
| Micro (legal, captions) | `0.8125rem` / 1.4 | 400 | Bricolage | only for genuinely secondary text |

Rules that are not negotiable:

- **Never lighten the ink or darken the paper** to make a design work. The
  contrast values in doctrine §3 and §8 are the contract (all pairs ≥ 5.1:1,
  stricter than WCAG AA's 4.5:1 `[E]`).
- **No handwriting font on the landing page.** Caveat/Kalam are a §10 accent
  for lesson headings and annotation labels; here they read as a different
  product.
- **No second typeface.** A serif "for warmth" or a mono "for tech" is a second
  brand.
- **Line length**: 45–75 characters for body copy. Wider is unreadable, narrower
  is a column of hyphens.
- **No text over images.** Ever. The contrast cannot be guaranteed on a photo you
  did not shoot.

## 4. The §10 guard

The lesson-page extension exists because a lesson is *studied*; a landing page is
*scanned*. Devices built for study break a page built for scanning.

**Forbidden on the landing page, without exception:**

| §10 device | Why it breaks here |
|---|---|
| The 36 px ruled-line grid and measured baselines | it signals "worksheet", and it fights the hero's proportions |
| Handwritten Caveat/Kalam headings and body | it reads as a mock-up of the product, not the product |
| Taped paper cards (`.zn-reveal`, `.zn-sim`, `.zn-check`) | "interactive object" affordance with no object behind it |
| The sticky lesson language bar | a lesson control; on a landing page it is a second navigation |
| The voice dock (sheet, tab, mic states) | it belongs to a page where the student is already studying |
| Lesson meta line ("Class 10 · Physics" as chrome) | fine as *content* in the hero, wrong as a page label |
| Row-quantised layout and `--page-w` 47 rem column | a reading column for prose, not a marketing composition |

The reverse error is just as real: a lesson page that ignores §10 is not "on
brand", it is incomplete. Both directions are doctrine §0 scope errors.

**The test:** if a device appears in doctrine §10 and not in §1–§9, it is a
lesson device. Ask "would this appear on a build-in-public post visual?" — if
yes, it belongs; if it only makes sense with a chapter open, it does not.

## 5. The banned list

Each item is banned for a reason, and the reason is the test.

| Banned | Why | The test |
|---|---|---|
| **Gradients**, mesh, blobs, glows | the doctrine bans them, and they are the visual signature of generic AI products | is any colour not a §3 token? |
| **Glassmorphism**, blur, translucency | reads as a template from 2021 and destroys contrast | is anything translucent? |
| **Stock photography** | a photo of a person who does not use the product is a lie with good lighting | is this a real user, a real artifact, or the product? |
| **3D renders, spheres, floating devices** | decoration that says nothing about the product | would the page lose information if it were removed? |
| **Abstract "AI" imagery** — neural nets, glowing brains, robot hands, sparkles | the reader does not care how it is built, and the imagery signals a wrapper | does this image depict something the product does? |
| **Corporate icon sets** — uniform line icons in coloured circles | the doctrine's anti-pattern list names corporate icons | is this icon doing work a word could not? |
| **Emoji as bullets or section markers** | it breaks the paper metaphor and reads as a chat app | would the page be worse without it? (yes, so remove it) |
| **Rounded-2xl cards with soft shadows** | the SaaS template signature | are corners square or 4 px? is there a shadow? |
| **Centred hero with two buttons and a logo row** | the SaaS hero; it says nothing specific | swap the logo: does the page still work? |
| **Carousels and auto-rotating headlines** | the reader sees one slide and loses the rest; also an a11y problem | can the reader read everything without waiting? |
| **Dark mode as the default** | paper is the brand; a dark landing page is a different product | is the ground `--paper`? |

## 6. Distinctive, not generic: three tests

"Make it distinctive" is not actionable. These three tests are.

1. **The silhouette test.** Squint until the text is illegible. Does the page
   have a shape you could recognise across a room — one dominant artifact, one
   asymmetric block, one mark? Or is it four stacked bands of equal weight?
2. **The swap test.** Put a competitor's wordmark in the top-left. Does the page
   still make sense? If yes, it is a template with your copy in it.
3. **The material test.** Is there at least one thing on the page that could
   only exist because *this* product exists — a real ray diagram, a real
   transcript, a real citation, a real number? A page made entirely of things
   any company could own is a generic page, however well set.

A page can pass 1 and 3 and still feel like AI slop if it fails 2. The swap test
is the one to run last, because it is the one that catches the most.

## 7. Mobile first, at 360 px

The default device is a low-end Android phone on a shared connection, held in
one hand. Design there and scale up.

- **Write the 360 px composition before the 1280 px one.** If the hero only works
  wide, it does not work.
- **No horizontal overflow at any width.** Do not hide a bug with
  `overflow-x: hidden`.
- **Touch targets ≥ 44 px** (the frozen frontend plan's target, PLAT-08; WCAG 2.2
  requires 24 px as the AA minimum `[E]`, the doctrine requires ≥ 40 px inside
  lesson rows `[R]`).
- **Body text ≥ 16 px** so mobile browsers do not zoom on input focus.
- **Never text over an image**, and never a full-bleed hero that pushes the
  headline below the fold.
- **The artifact scales by aspect ratio**, never by fixed pixel dimensions.
- **Respect safe areas** (`env(safe-area-inset-*)`) on notched devices.
- **Test in sunlight.** Paper-yellow with graphite labels is designed for it;
  check that the 40% hairline and the annotation survive glare.
- **No hover-only affordance.** Everything reachable by tap and by keyboard.

## 8. Colour use beyond the palette

Two colours may appear that are not in §3, and only as **content**, never as
chrome:

1. **The artifact's own colours** — a screenshot contains whatever the product
   contains. That is fine; it is a photograph of a real thing.
2. **A source's own mark** — if a citation needs a publisher's logo, it is
   content, sized to the caption scale, and never used as decoration.

Everything else — a coloured section background, a tinted card, a brand-accent
button — is a new token and therefore a doctrine change, not a page decision.

## 9. What this file will not do

- It will not give you a hex value, a font size, or a spacing number that the
  doctrine does not already own, except in §3 where the derivation is labelled.
- It will not decide the page's argument. If the art direction is carrying the
  argument, the copy has failed.
- It will not survive a founder visual verdict on its own. The verdict needs a
  real page at 360 px and 1280 px, with real content, in a browser.
