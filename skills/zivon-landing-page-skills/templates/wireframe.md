# Wireframe

Draw 360 px first. The desktop layout is a consequence, not a starting point.
Copy the grids, annotate them, and keep them in the PR next to the screenshots.

---

## 1. The 360 px first screen

```
+--------------------------------------+  <- safe-area top
| ZIVON            [ Open a chapter ]  |  wordmark + one action
+--------------------------------------+
|                                      |
|  H1, 800, 2.75rem, <= 9 words        |
|  one word pen-underlined             |
|                                      |
|  Subhead, 2 lines max:               |
|  who it is for + the mechanism       |
|  + the de-risking fact               |
|                                      |
|  +--------------------------------+  |
|  |  ARTIFACT                      |  |
|  |  (real screenshot, 4:3,        |  |
|  |   taped corners, one circle)   |  |
|  +--------------------------------+  |
|                                      |
|  [  Open a chapter  ]  44px min      |
|  no account needed                   |
|                                      |
|  Class 9-10 Physics  EN / हिं / Hinglish  |
+--------------------------------------+
```

Rules for this screen:

- The H1 is the first thing painted, in HTML, not in an image.
- The artifact is optional **only** if a proof line replaces it.
- The CTA is above the second scroll on a 640 px-tall viewport.
- The language sample is a real string, not a badge row.
- No cookie banner, no newsletter modal, no chat bubble.

## 3. The 1280 px hero

```
+-------------------------------------------------------------------+
| ZIVON                    courses   method   log in   [ start ]    |
+-------------------------------------------------------------------+
|                                   |                               |
|  H1 (5rem, 800)                   |   +-----------------------+   |
|  one word pen-underlined          |   |  ARTIFACT             |   |
|                                   |   |  real lesson page     |   |
|  Subhead (1.25rem, 2 lines)       |   |  one pen circle       |   |
|                                   |   |  2px hard offset      |   |
|  meta: Class 9-10 · EN/हिं/Hinglish |   |  tape at 2 corners    |   |
|                                   |   +-----------------------+   |
|  [ Open a chapter ]  no account    |                               |
|                                   |   caption: what it is, 1 line  |
|                                   |                               |
+-------------------------------------------------------------------+
        ^ text column ~48%                     ^ artifact ~44%
```

Rules:

- The type column is narrower than the artifact. Text is read in a column.
- One asymmetry only. Do not also rotate the headline.
- The annotation lives on the artifact if the headline refers to it.
- The caption under the artifact is a chance to say one true thing, not a label.

## 4. Annotation placement

| Where | Allowed | Not allowed |
|---|---|---|
| On the artifact, circling the anchor chip or the moving quantity | yes | circling a decorative element |
| On one word in the H1 | yes, if the artifact cannot carry it | on a link or a button |
| On a number that is the proof ("20 s") | yes | on a second number |
| Anywhere else | no | — |

One per screen. Generated by the doctrine's pen algorithm (§4.1), never by
`text-decoration` or `border-bottom`.

## 5. Artifact spec

Fill this in before the visual build:

```
What it is:            <real screenshot | real transcript | real diagram>
Source:                <route + commit + viewport>
Viewport captured:     360 x 640  |  1280 x 800
Format:                AVIF (fallback WebP), explicit width/height
Treatment:             taped corners, 2px hard offset, one pen circle
Alt text:              <describes what it shows, not "screenshot">
Caption:               <one true sentence>
Owner:                 <who re-captures it when the product changes>
```

An artifact without an owner goes stale in a month and becomes a false claim.

## 6. Layout checklist

- [ ] 360 px drawn before 1280 px
- [ ] No horizontal overflow at 360 / 390 / 768 / 1280
- [ ] CTA visible without scrolling on a 360×640 viewport
- [ ] Body text ≥ 16 px; touch targets ≥ 44 px
- [ ] Corners square or 4 px; no soft shadows; no gradients
- [ ] One pen annotation, one screen
- [ ] Artifact is real and has an owner
- [ ] Palette is §3 only, plus the artifact's own content colours
- [ ] Section separators are space and one hairline, not cards
- [ ] The page reads with CSS disabled (content order intact)
- [ ] No §10 device anywhere (ruled grid, handwritten body, taped card as UI, language bar, voice dock)

## 7. What never goes in the hero

- A video that must play before the page makes sense
- A carousel or a rotating headline
- A form
- A second button of equal weight
- A logo wall
- A stock photo
- A gradient, a blob, or a 3D render
- A slogan that names the category instead of the outcome
- A cookie or newsletter overlay
