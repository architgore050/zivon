# Open Questions (SP3-OBS)

Numbered, owned, closable. An OQ never blocks the build path it is not on: each item names what proceeds anyway and what waits. Format: **OQ-n — question / impact / owner / closes when.**

**OQ-1 — Base branch was absent on the remote.** The brief's `feature/backend-db-storage-spec` does not exist on `origin` (verified `git ls-remote` 2026-11-09); this spec chains from `main` @ `0a43d95`. Impact: none on content — every doc here is additive; the merge agent applies the patches onto the real base branch. Owner: merge agent. Closes: when patches are applied to the real base and the 2–3 line map edits are reconciled (they may need a 3-way merge if Wave-0/S0 also touched those lines).

**OQ-2 — Sync-policy/data-classification alignment.** `docs/backend/sync-policy.csv` / `data-classification.csv` / `storage-tiering.md` were not present on the available base, so ADR-0018's retention table and sync triggers (daily 03:30 IST + 200 MB cap, retain-until-synced) are this spec's proposal, marked `[ASSUMPTION]`. Impact: none on code paths (the module reads only its own constants); the cold-sync Job's schedule constants may shift. Owner: backend-db-storage agent. Closes: reconcile the two retention tables at merge; where they differ, the stricter TTL wins.

**OQ-3 — Admin-surface reconciliation (backend-spec §6.3).** The brief directs the dashboard to read core-backend's §6.3 admin surface rather than invent a parallel one; §6.3 was absent on this base. This spec defines a minimal read-only + two-button surface (`dashboard-spec.md` §3/§5) and does NOT claim §6.3 conformance. Impact: endpoint paths (`/admin/...`) may need renaming to match the backend's surface. Owner: backend-db-storage agent + merge agent. Closes: rename-or-ratify at merge; the view/audit contracts are unaffected.

**OQ-4 — Test-suite results ingestion.** V2 (dashboard) needs per-suite pass/fail; the test CronJob currently emits only Job status + logs. Proposal: the S-series test agent adds `test.suite.*` events (rows reserved in `instrumentation-map.csv` as declared contracts for parallel agents). Impact: V2 renders Job-status-only until those events exist (honest, degraded-by-design). Owner: test/CI agent. Closes: `test.suite.passed/failed` rows appear in the map with emitters.

**OQ-5 — CSP carve-out sign-off (F-1).** Generated lesson pages ship `connect-src 'none'` (locked posture); the frontend event contract requires `connect-src 'self'` for the same-origin beacon (`spec.md` §8). No external egress is introduced; the change touches the factory's CSP emission + no lint weakening. Impact: EVT-Fxx events buffer in sessionStorage (≤ 50, FIFO) until the carve-out ships. Owner: founder (posture change) → factory agent (one-line change + test). Closes: founder sign-off recorded; interim buffering is the default-safe behavior either way.

**OQ-6 — AGENTS.md "log transcripts" line.** `AGENTS.md` Documentation/non-negotiables text says to log "enough to debug conversations (transcripts, latency, errors)"; A-02 (binding) forbids transcripts in structured logs. This spec resolves it as: logs carry `session_id`/`turn_id` + timings; transcripts live in DB rows (7-day TTL) joined by ID. Impact: none (spec follows A-02); the AGENTS.md line deserves a one-word amendment ("transcript references") by its owner. Owner: founder. Closes: AGENTS.md line-edit (this agent deliberately did not touch that line — outside the map-edit scope).

**OQ-7 — Postgres tenancy for logs.** ADR-0018 puts `log_events` on the backend's Postgres instance; the backend agent's isolation NFRs might require a separate role/database or forbid logging tenancy. Impact: the module reads `ZIVON_LOG_DSN` — pointing it elsewhere is config, not code. Owner: backend-db-storage agent. Closes: DSN shape + role grants confirmed; otherwise this ADR reopens with evidence.

**OQ-8 — Cold provider specifics.** ADR-0018/ADR-0017 reference ADR-0004 (cold provider) + ADR-0006 (sync mechanism) by interface only (NDJSON exports, verify-then-drop). Provider specifics (endpoint, credentials class, bucket layout) were absent on this base. Impact: the `log-sync` Job's export target config; the verify-then-drop ordering is fixed regardless. Owner: backend-db-storage agent (ADR-0004 owner). Closes: ADR-0004/0006 available and the export target config lands in `k8s/infra.env`.

**OQ-9 — EVT-ID reconciliation.** The frontend contract uses `EVT-F01`–`EVT-F12` (an explicit sub-range for frontend-originated events) because the master EVT- catalogue (`docs/product/backend-handoff.md`) was absent on this base. Impact: cosmetic (IDs); event NAMES and properties are the binding part of the contract. Owner: merge agent. Closes: EVT-Fxx mapped into the master catalogue (or the catalogue adopts the F-subrange as-is).
